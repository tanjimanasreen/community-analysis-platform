# 28. GitHub OIDC Architecture

Plan 097 creates an AWS GitHub OIDC integration using:

```text
https://token.actions.githubusercontent.com
```

Audience:

```text
sts.amazonaws.com
```

Repository:

```text
tanjimanasreen/community-analysis-platform
```

Development branch:

```text
refs/heads/dev
```

The exact `sub` claim MUST be verified by the HUMAN before bootstrap.

Plan 097 supports exactly two approved subject forms:

1. Legacy name-based form:

```text
repo:tanjimanasreen/community-analysis-platform:ref:refs/heads/dev
```

2. Immutable repository-ID form:

```text
repo:tanjimanasreen@<OWNER_ID>/community-analysis-platform@<REPO_ID>:ref:refs/heads/dev
```

The human must supply the exact verified subject through:

```text
-c github_oidc_subject="<EXACT_SUBJECT>"
```

or:

```text
GITHUB_OIDC_SUBJECT="<EXACT_SUBJECT>"
```

The CI/CD bootstrap must fail closed when the subject is absent. No implicit subject defaulting occurs during CI/CD bootstrap synthesis.

Trust policy condition strictly enforces exact `StringEquals` for both:

```text
token.actions.githubusercontent.com:aud = sts.amazonaws.com
token.actions.githubusercontent.com:sub = <exact supplied subject>
```

No `StringLike` is used. Wildcard patterns (`*`), `main` branch, other branches, pull request subjects, environment subjects, and other repositories/owners are strictly rejected.

Production trust is Plan 098.

```text

The pagination helper does not truncate at an arbitrary event count (e.g. 5,000 events), ensuring that completion markers in large real-data runs (e.g. 13,000+ events) are captured, while maintaining a bounded page-level safety guard (100 pages).

Full authenticated API smoke testing is a CD responsibility (`cd.yml`).

- Cognito temporary-user administration;
- full API smoke suite execution;
- deployment permissions.
